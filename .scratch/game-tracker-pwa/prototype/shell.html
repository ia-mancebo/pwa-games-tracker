¿Con qué stack se construye?

Las tres opciones comparten Vite y vite-plugin-pwa para el service worker, y ninguna cambia lo decidido en los research: Worker proxy delante de IGDB, y .json + IndexedDB como almacenamiento.

Svelte 5 + Vite recomendada

runtime ~12 KB · reactividad por runes · SFC compilados

  • Runes encajan con el dominio: filtros de biblioteca y espejo IndexedDB son estado reactivo puro.
  • Bundle pequeño y sin virtual DOM: arranque rápido en un Android 11 modesto.
  • Ecosistema menor que React; menos ejemplos para casos raros.

Vanilla TS + Vite

~0 KB de runtime · web estándar · este prototipo funciona así tal cual

  • Cero dependencias de framework: el archivo que estás viendo es la prueba de viabilidad del shell.
  • Control total del render y del service worker.
  • Estado, listas y render hechos a mano: más andamiaje propio que mantener.

React 19 + Vite

~50–60 KB de runtime · ecosistema máximo

  • Ecosistema y ayuda de IA abundantes; camino fácil si el proyecto crece de manos.
  • Peso y ceremonia sobredimensionados para tres pestañas de datos locales.
  • Re-renders y gestión de dependencias que aquí no compran nada.

Restricciones fijas: GitHub Pages estático · 100 % offline · sin backend propio (el Worker de IGDB va aparte). Este prototipo usa datos ficticios y código desechable. Lo que cierra este ticket: la dirección visual (A/B/C o mezcla) y la elección de stack.
